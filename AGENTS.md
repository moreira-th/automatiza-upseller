## Padrões de Código

### React valueTracker — SEMPRE usar nativeSetter
O UpSeller usa React/Ant Design. Atribuição direta `input.value = X` **não funciona** — o valueTracker do React não detecta:
```js
var nativeSetter = Object.getOwnPropertyDescriptor(window.HTMLInputElement.prototype, 'value').set;
input.focus();
nativeSetter.call(input, valor);
input.dispatchEvent(new Event('input', { bubbles: true }));
input.dispatchEvent(new Event('change', { bubbles: true }));
input.blur();  // React usa onBlur para commitar estado
```

### Aplicar/ler valores SEM rolagem — API do vxe via MAIN world (preferido)
O UpSeller usa **vxe-table** com *virtual scroll*: só ~8 linhas ficam no DOM, então varrer por rolagem é lento e **deixa linhas de fora** (principalmente o fim da lista). Em vez de rolar, acesse o **estado** da tabela — instantâneo e 100% completo.

**Regra de ouro:** `elemento.__vue__` (e a instância do vxe) **só existe no mundo MAIN da página**. Content scripts rodam em mundo isolado e **NÃO** enxergam essas propriedades JS (só o DOM). Por isso, todo acesso ao vxe deve passar pelo `background.js` via `chrome.scripting.executeScript({ world: 'MAIN' })`.

Descobrir os dados (console da página / mundo MAIN):
```js
var vm = document.querySelector('.vxe-table').__vue__;  // instância Vue do vxe
var full = vm.getTableData().fullData;                  // linhas do estado (produtos com .children = variações)
vm.getData();                                           // todas as linhas achatadas
// métodos úteis: getRowById, getRowid, scrollToRow, reloadData, updateData, getCell
```
Cada variação costuma ter: `id`, `attrMap` (ex.: `{Cor, Tamanho}`), `price`, `discount`, `parentId`.

Editar: basta **atribuir no objeto reativo** — o vxe/`<input>` do DOM atualiza sozinho (Vue 2 reativo, `__ob__`):
```js
variacao.discount = '58';   // o <input> correspondente passa a mostrar 58
// sincronize também product.variationList (é cópia por id, se existir)
```

**Ponte content script → background → MAIN world:**
```js
// content script (mundo isolado)
chrome.runtime.sendMessage({ action: 'xxx-vxe-get' }, function (resp) { /* resp.variacoes */ });

// background.js
if (msg.action === 'xxx-vxe-get') {
  chrome.scripting.executeScript({
    target: { tabId: sender.tab.id },
    world: 'MAIN',
    func: () => {
      var vm = document.querySelector('.vxe-table').__vue__;
      var full = vm.getTableData().fullData || [];
      var lista = [];
      full.forEach(p => (p.children || []).forEach(v => lista.push(v)));
      return { variacoes: lista };
    }
  }).then(r => sendResponse(r[0].result)).catch(e => sendResponse({ error: e.message }));
  return true; // resposta assíncrona (obrigatório com executeScript)
}
```

**Pegadinhas (aprendidas na Shein):**
- **Cores novas compartilham o MESMO `id`** (id provisório, não salvo) → chaveie o mapa de aplicação pelo **índice (`idx`)** do `fullData`, **nunca** pelo `id` (senão uma entrada sobrescreve a outra e todas recebem o último valor).
- **Cores novas aparecem com ~300ms de atraso** → aguarde estabilizar (total constante em 2 leituras) + faça uma 2ª passada.
- **Anúncio ativo/publicado:** variação **publicada** = **`variantId` preenchido** → preço **bloqueado** (não alterar); **nova** = sem `variantId` → editável. Regra: pular só o **preço** das publicadas, mas **ainda aplicar peso/pacote** (inputs editáveis). No rascunho, `variantId: null` → editável.
- Outros sinais de status no estado: `hasShelf`, `publishAuditStatusObj` (`Ativado`/`Pausados`), `pendingReviewStatus`.
- Documentação completa: `aplicar-valores-sem-rolagem-vxe.md` (raiz).

### Cuidados

- NUNCA usar `window.postMessage` — conteúdo isolado no Chrome MV3
- Acesso ao mundo MAIN (ex.: `__vue__` do vxe) é sempre via `background.js` + `chrome.scripting.executeScript({ world: 'MAIN' })` — **nunca** direto no content script (isolado não enxerga)
- Service Worker é stateless — dados em `chrome.storage.local` ou `chrome.storage.session`
- `expandirAtributos()` usa `el.innerText` (não `textContent`) — `textContent` inclui ancestors causando falsos positivos
- `aplicarCoresNaPagina()` é fire-and-forget (não `await`) — não compartilha DOM com etapas seguintes
- Multi-aba paralelo: estado em `chrome.storage.session` chave `multiTabParallel`. `tileTabs()` cria as janelas **em paralelo** (`Promise.all`, sem `sleep(200)` por janela) — antes eram sequenciais e levavam ~5s com 10 abas (era o gargalo do "início lento" do multi-aba, medido: 5,0s → 3,0s; o resto é o próprio Chrome criando as janelas, ~330ms cada). No modo paralelo **não há timeout**: se alguma aba não responder (ex.: content script invalidado por recarregar a extensão sem recarregar a página), o multi não finaliza.
- **Editar em Massa (Shein) — Pacote**: o campo `ups-ma-epkg` é um input **oculto** com o valor `CxLxA` (a macro/presets/estado continuam lendo/gravando **só ele**); os 3 campos visíveis `ups-ma-epkg-c`/`-l`/`-a` compõem o valor quando os três estão preenchidos (incompleto = vazio = não altera nada) e são preenchidos pelos restores via `definirPacoteShein()`. Mudança **só visual**.
- **Editar em Massa (Shein) — layout e SKU Base**: linha 1 = **SKU Base** (novo, `ups-ma-sku-base`) + Preço regular (desativado); linha 2 = Quantidade | Peso | Pacote (grid `minmax(0,1fr)` nas colunas, senão o `min-content` do pacote esmaga as outras). O SKU Base preenche o **"N° do Anúncio"** da página (`preencherNumeroAnuncio`) quando o **Numerar SKU do Multi-Aba** está vazio (o Multi-Aba tem **prioridade**; ambos vazios = nada acontece). O SKU Base **nunca é salvo** (preset/estado) e é limpo após o uso — evita aplicar o SKU em outro anúncio.
- **Pacote em 3 campos / SKU Base nos modais verdes e na Shopee**: helpers genéricos no `core.js` — `upsInitPacote3(prefixo)` (monta a composição e preenche C/L/A a partir do oculto) e `upsDefinirPacote3(prefixo, valor)` (restores); prefixos: `ups-ma` (Shein overlay **e** Shopee overlay), `ups` (Shein verde), `sp-ma` (Shopee verde). A Shein overlay (azul) mantém o `definirPacoteShein` próprio. **Shein verde** (`abrirDialogPrecos`, `upseller-precos-overlay`): SKU Base `ups-sku-base` → N° do Anúncio no passo `skuBase` (antes do SKU, depois do remap). **Shopee azul** (`abrirDialogShopee`) e **verde** (`abrirModalPrecoShopee`, `ups-sp-modal`): SKU Base (`ups-ma-sku-base`/`sp-ma-sku-base`) → **SKU Principal** via handler `shopee-sku-principal-set` (mundo MAIN, acha pelo label "SKU Principal"); no multi-aba o `numeroSku` tem prioridade sobre o `skuBase`. SKU Base nunca é persistido e é limpo após o uso.

Multi-selects do Ant: limpar clicando **um** `x` por vez e aguardando (`limparSelectMultiplo`) — clicar em todos de uma vez falha (elementos obsoletos após o re-render) e clicar numa opção **já selecionada** a desmarca (por isso limpamos antes e pulamos `ant-select-dropdown-menu-item-selected`). Alterações em content scripts exigem **recarregar a extensão** (não basta recarregar a página)
- **Atributos via estado Vue (Shein, `/shein/edit/*`)**: a seção de atributos **não** é vxe-table, mas o valor selecionado vive no estado do componente `AttributesInfo` (achado via `#app.__vue__` → `$options.name === 'AttributesInfo'`), em `_data.attrShowData[id].inputValues`: `isList`=id (número), `isTags`=[ids], `isString`=texto, `isSelectAndNumber`=`{type,number}` + `selectData.valueArr=[{type,number,id}]`. As opções (rótulo↔id) estão em `valueList`; o payload de save é montado por `getAttrPostData()` **a partir desse estado**. Handlers `background.js` → `shein-attr-get` / `shein-attr-set` (mundo MAIN, itens por **rótulo**; `limpar:true` reseta todos). `extras.js` → `atributosViaBackground()`/`lerAtributosViaBackground()`; `aplicarAtributo()` e `limparAtributosCustomizados()` usam o estado com **fallback DOM**. Validado: payload (`getAttrPostData`) idêntico antes/depois de reaplicar o preset
- **Mídia — "Ajustar Imagens" (Mercado Livre e Temu):** o menu do botão ganha, no topo, **"A partir do meu computador"** e **"Link da Tabela"** (`extras.js` → `_upsCriarBotaoImagemMassa`, gated por `/mercado/` ou `/temu/`), que inserem a MESMA imagem em **todas** as linhas/variantes (anexando, sem apagar). A fonte da Mídia é o componente **`VariantsImgModule.selfVariantsList[i].imgList`** (`[{id,url}]` — MESMO componente em todas as plataformas); gravar **só o `imgList`** e salvar **persiste** (validado no Mercado, sem espelhar no store). Handlers genéricos no `background.js` (mundo MAIN): **`ups-media-upload`** (sobe um `dataUrl` de arquivo OU baixa um `url` no navegador — CORS — e sobe pela API `media/file/upload/generate-sign` → PUT → `callback`, devolvendo a URL hospedada), **`ups-media-aplicar`** (anexa as URLs em todas as variantes) e **`ups-media-snapshot`** (para detectar o que o app inseriu). Funções no `mercado.js`: `upsMediaArquivos()`, `upsMediaLinkDialogo()` (reusa `upsDialogShein` com os últimos links), `upsMediaInserirNativo()` (fallback: fluxo nativo "A Partir de Web (Link)" na 1ª linha). Cuidado: `__vue__` **não** existe no mundo isolado — por isso o snapshot/aplicação vão sempre pelo background (MAIN).

**Modal "Editar Atributos" em massa** (`/shein/active`, `/shein/drafts` e **`/mercado/up-drafts`**): componentes `AttrBatchEditAttrModal` (abas = lojas em `allShopDataArr[]`) e `AttrEditItem` (`attrObj.data[id]` com `check` + `inputValues`). Handlers `shein-attr-bulk-cats` (categorias deduplicadas por `categoryId`, com `shopIds`/`nProd`) e `shein-attr-bulk-apply` (recebe **`shopId`** — o **índice da aba é instável**, a ordem muda com a aba ativa — troca de aba, expande a categoria, aplica `check`+`inputValues` e atualiza `renderObj` do `categoryList`). `abrirDialogAtributosDrafts()` lista todas as categorias de todas as abas e o Executar percorre as abas; seletor do botão: `.ant-modal-root.my_modal.my_tab_modal` (injetado via `monitorModalEditarAtributos`). **Mercado Livre** (`/mercado/up-drafts`): botão injetado em `.list_btn` via `monitorToolbarDrafts` (mesmo fluxo: "Ações em Massa" → "Editar Atributos"), com handlers próprios `mercado-attr-bulk-cats` / `mercado-attr-bulk-apply` (`AttrBatchEditAttrModal` + `AttrEditItem`, dados em **`attrObj.data`**) e presets da chave `bibliotecaAtributosMercado`. No Mercado as tags usam **TEXTOS** (nomes) e não os ids do catálogo; em `isString` com `valueList`, casa o rótulo e usa o **id** (senão grava o texto livre).
- **Atributos via estado Vue (Temu, `/temu/edit/*` e `/temu/create`)**: seção `#attributes` → `AFormModel.$props.model` (objeto chaveado por `prop`, cada entrada com `attributeName`/`inputValues`/`attrConfig`/`valueList`); cada campo é um componente `InputControl` com `selfValue`. **Select simples** (`attrConfig.isSelect`): `MySelect.setValue(vid)` + `emitVal(vid)` — atualiza a UI e o `inputValues` do modelo. **Composto** (`attrConfig.isCombo`, tipo "mat|pct"): `ic.selfValue = [{vid,num,valueUnitId}]` + `ic.onAttrBlur()`. **Input** (`isInput`): `ic.selfValue.value` + `onAttrBlur()`. O valor do select é o **`value` numérico** do `valueList` (não o `id`, que é string). Handler `background.js` → `temu-attr-set` (mundo MAIN, itens por **rótulo**; `limpar:true` limpa tudo). `temu.js` → `atributosTemuViaBackground()`; `aplicarAtributosTemu()` expande "Mais atributos" (para montar os controles), usa o estado e cai para o DOM se algum atributo faltar
- **Confirmar Cores (Temu)**: a seção de cores é um checkbox-group com **abas por tom** (`ul.group_list` dentro de `.my_card.variants_attr_card`) + a lista `ul.variant_val_List`. **TODAS as cores de TODOS os tons ficam no DOM ao mesmo tempo** (só as do tom ativo ficam visíveis) — clicar no checkbox de uma cor "oculta" funciona e já a contabiliza no tom correto (`.num` da aba). - **Subespecificação de Tamanho (Temu)**: a seção Tamanho tem **2 menus** — o 1º é o **grupo** (`group.name`: "Tamanho no Brasil"/"Tamanho"/"Tamanho universal") e o 2º o **subgrupo** (`subGroup.name`: "Alfa"/"Numérico") — e a lista `ul.variant_val_List`.
